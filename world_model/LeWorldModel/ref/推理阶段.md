

### 实例类比

- **训练阶段**：你花1小时观察别人推箱子，学会了"箱子只能被推不能拉、推左边箱子往右走、撞墙箱子不动"这些通用物理规律。这个过程只做一次，学会了就永远会。
- **规划阶段**：现在给你一个新的推箱子关卡（箱子在A点，要推到B点），你不会真的在屏幕上瞎按键盘试错（会浪费时间、可能把箱子推到死角），而是**在脑子里先模拟100种推法，找到最快能到B点的那条，再去键盘上执行**。
  
  ### 对应论文技术本质
  
  | 维度   | 训练阶段                   | 规划阶段                     |
  | ---- | ---------------------- | ------------------------ |
  | 核心目标 | 学习环境通用物理规律（箱子怎么动、墙怎么挡） | 用已学规律，解决"把箱子推到指定位置"的具体任务 |
  | 试错地点 | 离线数据集（别人推箱子的录像）        | 模型自己的"脑子里"（潜空间）          |
  | 输出   | 编码器+预测器的参数             | 接下来要按的键盘按键序列             |

## 逐步骤双轨详解（论文技术 ↔ 推箱子实例）

### 论文任务设定

- 环境：2D网格世界，有1个箱子、1面墙、1个红色目标点
- 动作空间：上下左右4个方向（每次按一个键，箱子动一格）
- 目标：把箱子从初始位置推到红色目标点

---

### 步骤1：编码初始状态和目标状态

#### 你作为人会怎么做（实例）

1. 睁开眼睛看屏幕：现在箱子在左上角(1,1)，我在箱子左边 → 这是**初始状态**
2. 看一眼目标：红色点在右下角(5,5) → 这是**目标状态**
3. 你不需要知道中间怎么走，只需要记住"我现在在哪"和"我要去哪"
   
   #### 对应论文技术操作
   
   ```python
   # 输入：真实环境的两张图片
   initial_obs = env.get_observation() # 初始画面：箱子在(1,1)
   goal_obs = env.get_goal_observation() # 目标画面：箱子在(5,5)
   # 用训练好的编码器，把高维像素图片压缩成低维潜向量
   z_initial = encoder(initial_obs) # shape: (192,) 192维潜向量
   z_goal = encoder(goal_obs) # shape: (192,)
   ```
   
   #### 论文为什么这么设计？
- 原始像素图片是(3,64,64)=12288维，压缩成192维潜向量后，计算量直接降低64倍，这是规划能做到"不到1秒完成"的核心原因
- 编码器已经在训练阶段学会了提取关键信息（箱子位置、我的位置、墙的位置），扔掉了无关的背景像素

---

### 步骤2：初始化CEM优化器

#### 你作为人会怎么做（实例）

你给自己定了4条试错规则，用来快速找到最好的推法：

1. 我每次只规划**接下来的5步按键**（比如：右→右→下→下→右），不想更远的事
2. 每次随机想**300种不同的5步按键组合**
3. 每次试完300种，只留下**最好的30种**（前10%）
4. 这样反复试**10次**，就能找到最优的推法
   
   #### 对应论文技术操作
   
   ```python
   # 初始化CEM优化器参数（论文官方默认值，所有任务通用）
   cem = CEMOptimizer(
   planning_horizon=5, # 规划视界H=5：每次规划5步动作
   num_samples=300, # 每次采样300个候选动作序列
   elite_ratio=0.1, # 精英比例10%：保留前30个最好的
   num_iterations=10 # 迭代10次收敛
   )
   ```
   
   #### 论文为什么这么设计？
- **规划视界H=5**：预测器自回归展开会累积误差，推5步的误差还很小，推10步以上误差就会大到没用
- **采样300个+迭代10次**：在"计算速度"和"找到最优解"之间的最佳平衡，再多会变慢，再少找不到最优解
- **精英比例10%**：既能保留好的方向，又不会过早陷入局部最优

---

### 步骤3：迭代优化动作序列（规划核心！）

这是整个规划阶段最耗时也最关键的部分，**全程在模型的脑子里（潜空间）完成，不需要和真实环境交互**。

#### 第1次迭代（共10次）

##### 3.1 采样候选动作序列

- **你会怎么做**：随机想300种不同的5步按键组合，比如：
  - 序列1：[右, 右, 下, 下, 右]
  - 序列2：[下, 下, 右, 右, 右]
  - 序列3：[左, 上, 上, 下, 下]（明显没用的序列）
  - ...（共300种）
- **对应技术操作**：从均值为0、方差为1的高斯分布中，采样300个长度为5的动作序列
- **为什么用高斯分布**：简单高效，且能覆盖所有可能的动作组合
  
  ##### 3.2 潜空间展开（核心中的核心）
- **你会怎么做**：在脑子里模拟每一个动作序列的结果，比如：
  - 模拟序列1：按右→箱子到(2,1)→再右→(3,1)→再下→(3,2)→再下→(3,3)→再右→(4,3)
  - 模拟序列2：按下→我到(1,2)→再下→(1,3)→再右→撞墙，箱子不动
  - 模拟序列3：按左→我撞墙，箱子不动
- **对应技术操作**：用训练好的预测器，自回归地展开5步，得到每个序列的最终潜状态
  
  ```python
  z_current = z_initial.repeat(300, 1) # 复制300份初始状态，并行模拟
  for t in range(5):
  z_current = predictor(z_current, actions[:, t]) # 预测下一步潜状态
  z_final = z_current # 300个序列的最终潜状态，shape: (300, 192)
  ```
- **为什么叫"潜空间展开"**：所有模拟都在192维的潜空间里进行，不是在像素空间，速度极快
  
  ##### 3.3 计算代价（判断好不好）
- **你会怎么做**：给每个模拟结果打分，分数越低越好：
  - 序列1的结果：箱子在(4,3)，离目标(5,5)的距离是√[(5-4)²+(5-3)²]≈2.24 → 分数2.24
  - 序列2的结果：箱子在(1,1)，离目标距离是√(4²+4²)≈5.66 → 分数5.66
  - 序列3的结果：箱子在(1,1) → 分数5.66
- **对应技术操作**：计算每个最终潜状态和目标潜状态的L2距离（论文唯一代价函数）
  
  ```python
  cost = torch.sum((z_final - z_goal) ** 2, dim=1) # shape: (300,)
  ```
- **为什么只用L2距离**：最简单、最通用，不需要任何任务特定的奖励函数，训练好的模型可以零样本适应任意目标
  
  ##### 3.4 选择精英序列+更新采样分布
- **你会怎么做**：
  1. 把300个序列按分数排序，留下分数最低的前30个（精英序列）
  2. 计算这30个精英序列的均值和方差
  3. 下一次迭代，就在这个均值和方差附近采样新的300个序列，而不是完全随机
- **对应技术操作**：
  
  ```python
  elite_indices = torch.argsort(cost)[:30] # 选前30个最好的
  elite_actions = actions[elite_indices]
  new_mean = elite_actions.mean(dim=0)
  new_std = elite_actions.std(dim=0)
  ```
- **为什么这么做**：快速缩小搜索范围，不用试所有可能的动作组合，10次迭代就能收敛到最优解
  
  #### 重复迭代10次
  
  每次迭代都在之前最好的序列附近采样新的序列，越往后，采样的序列越好，最终收敛到最优的5步动作序列。

---

### 步骤4：MPC执行+重新规划

#### 你作为人会怎么做（实例）

1. 你得到了最优的5步序列：[右, 右, 下, 下, 右]
2. 但你**不会把这5步全部按完**，而是**只按第一步"右"**
3. 按完后，你看一眼屏幕：箱子真的到了(2,1)，和你模拟的一样
4. 然后你**回到步骤1，重新规划接下来的5步**：现在初始状态是箱子在(2,1)，目标还是(5,5)
   
   #### 对应论文技术操作
   
   ```python
   # 执行最优序列的第一个动作
   best_action = best_sequence[0]
   env.step(best_action)
   # 获取新的观测，重新开始规划
   new_obs = env.get_observation()
   z_initial = encoder(new_obs)
   # 回到步骤2，初始化CEM，重新规划接下来的5步
   ```
   
   #### 论文为什么这么设计？（MPC的核心意义）
- 预测器不是完美的，模拟的结果和真实环境永远有微小误差
- 如果一次性执行完5步，误差会累积放大，最后可能差得很远
- 每执行一步就用真实环境的新观测重新规划，相当于不断纠正误差，保证最终能到达目标

## 最终：规划阶段得到了什么？

### 实例层面

你没有在屏幕上瞎按1000次键盘试错，而是在脑子里花了0.5秒模拟了3000种推法，最终**用最少的步数，把箱子推到了目标点**。

### 技术层面

- 得到了实时的最优动作序列，实现了从"像素输入"到"动作输出"的端到端控制
- 不需要任何任务特定的训练，同一个训练好的模型，可以推任意位置的箱子到任意目标点
- 规划速度比传统世界模型快48倍，接近实时控制

## 补充：论文中规划阶段的核心优势

1. **零样本泛化**：训练一次，就能解决任意初始位置、任意目标位置的推箱子任务，不需要重新训练
2. **无试错成本**：所有试错都在潜空间里完成，不会弄坏机器人、不会浪费时间
3. **速度极快**：单张L40S GPU上，一次完整规划（10次迭代）不到0.1秒，完全满足实时控制需求
4. **鲁棒性强**：MPC机制能有效纠正预测误差，即使模型有小的预测错误，也能最终到达目标
